Summary:
machine sporadically failing to be created when adding machines or creating catalog

Description:
Customer reports intermittent VM creation failures when adding machines to an existing MCS catalog (or creating a new catalog) in Citrix Cloud / CVAD.
When adding a small batch (e.g., 5 machines) the operation succeeds. When adding a larger batch (e.g., 25 machines), a handful of machines fail.

Observed symptoms:
- Studio shows 5/25 machines as "Failed" with callback timeout / no completion reported.
- On the hypervisor side (vCenter), all 25 VMs are created successfully.
- Shortly after creation, 5 VMs enter a DeleteVM / Destroy_Task flow (cleanup).
- For those 5 VMs, DDC/Broker does not receive async completion callback from Cloud Connector/HCL pipeline.

Expected:
All 25 machines should be created and reported back to Studio successfully.

Actual:
20 machines succeed; 5 machines fail in Studio due to missing async callback and then are deleted by cleanup.

Affected Machines (failed in Studio):
- Win11-Office-VDI-VM07
- Win11-Office-VDI-VM12
- Win11-Office-VDI-VM18
- Win11-Office-VDI-VM22
- Win11-Office-VDI-VM24

4) Observe that ~5 machines fail and are later removed

Triage Notes / Root Cause Hypothesis:
The failure correlates with high concurrency provisioning where connector-side lock contention causes the RemoteHCL WCF client channel to fault/timeout after ~60 seconds.
When the WCF channel faults, RemoteHCL may still complete VM creation in vCenter, but the completion response/callback is not delivered back to the Broker/DDC.
Broker times out waiting for callbacks (60s) and marks machines failed; orchestration triggers cleanup -> DeleteVM.

Related logs (high-level):
- 03_CloudConnector_HclProxyTrace.csv: lock contention + WCF channel fault (CommunicationObjectFaultedException) around 60s.
- 04_RemoteHCL_ServiceTrace.csv: RemoteClientDisconnectedException after VM creations; operations complete but responses cannot be returned.
- 02_DDC_BrokerServiceTrace.csv: WaitForCallback timeout for 5 machines.
- 05_vCenter_HypervisorTrace.csv: VM create completed for all 25; later Destroy_Task for 5.
