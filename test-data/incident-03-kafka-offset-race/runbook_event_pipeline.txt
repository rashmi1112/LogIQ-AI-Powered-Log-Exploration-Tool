RUNBOOK: Event Pipeline Triage - Downstream State Inconsistency
================================================================
Version: 2.0
Last Updated: 2025-02-01
Owner: Platform Engineering

SCOPE
-----
This runbook covers cases where downstream consumers report inconsistent state after
receiving events through the StreamFlow event pipeline.

STEP 1: CONFIRM EVENT DELIVERY
--------------------------------
- Check Kafka consumer group lag for streamflow-events-cg.
  Acceptable lag: < 10,000 messages. Alert threshold: > 25,000.
- Verify events are being consumed (poll rate > 0).
- If lag is growing unbounded, escalate to Infrastructure (possible broker issue).

STEP 2: CHECK EVENT PROCESSOR HEALTH
--------------------------------------
- Review event_processor.log.csv for ERROR-level entries.
- Check for any failed batch processing (FailCount > 0 in BatchComplete events).
- If batch failures are present, check the specific event types failing.

STEP 3: CHECK FOR NETWORK PARTITION OR CONSUMER CRASH
-------------------------------------------------------
- Confirm all consumer nodes are healthy: kafka-consumer-03, kafka-consumer-07,
  kafka-consumer-11 (and any others in the consumer group).
- A crashed consumer will cause partition reassignment and potential message redelivery.
- If a consumer recently crashed and restarted, verify offset reset policy:
  accepted values: latest, earliest. Default: latest (no replay).

STEP 4: CHECK DOWNSTREAM INTEGRATIONS
----------------------------------------
- Confirm the customer's downstream service is receiving events (check their webhook logs).
- If events are being delivered but state is wrong, the issue may be in their application
  logic, not in the StreamFlow pipeline.

STEP 5: ESCALATION
-------------------
If steps 1-4 do not identify the cause, escalate to Platform Engineering with:
- Consumer group name
- Affected event types
- Time window
- Example event IDs that were affected

NOTE: This runbook does not cover duplicate event delivery scenarios. If duplicate events
are suspected, contact the Kafka Platform team. Offset management issues require a
separate investigation path not covered here.
